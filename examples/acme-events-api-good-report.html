Engineering recommendation This API is exceptionally well-built for mobile: 100ms p50 latency, cursor pagination with field filtering, full delta sync with tombstones, working ETag/304 caching, idempotent POST with replay confirmation, consistent machine-readable error schema, and comprehensive rate limit signalling — all at full or near-full points. The two issues blocking mobile shipment are (1) confirming PKCE in the authorization code flow (a documentation and config change, not a rewrite) and (2) adding a push/RTM mechanism for server-initiated event changes (new feature work). Resolve both, add a sandbox environment and changelog link, and this API reaches Mobile-ready with high confidence.
Conditions for approval 1. Confirm PKCE (code_challenge + code_verifier) in authorization code flow and document in OpenAPI spec — removes the blocker.
2. Implement RTM transport (WebSocket, SSE, or APNs/FCM) covering event-changed and booking-status events.
3. Provision a sandbox/staging environment with representative test data.
4. Publish a changelog linked from health endpoint or API documentation.
